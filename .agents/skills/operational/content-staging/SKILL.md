# Arize — content staging (master)

Last updated: 2026-05-31. Last run: 2026-08-19.

Step 0: Read [`../../../../references/agent-runtime.md`](../../../../references/agent-runtime.md).

Log line prefix: `[run-debug] workflow=content-staging | <PHASE> | <facts>`

## Destinations (by content type)

- **Blog drafts** → WordPress `status=draft` post on production
  `https://arize.com` via [`../wordpress/SKILL.md`](../wordpress/SKILL.md).
- **Glossary (glossary-term)** → WordPress `glossary` CPT draft via
  [`../wordpress/glossary/glossary-builder/SKILL.md`](../wordpress/glossary/glossary-builder/SKILL.md);
  the alphabetized `/glossary/` index page is regenerated by
  [`../wordpress/glossary/index-page-builder/SKILL.md`](../wordpress/glossary/index-page-builder/SKILL.md).
- **Buyer's guide** → Markdown in the agent's local `tmp/`, plus a Google
  Doc handoff (see the buyer's-guide agent's deliver step).
- **"Alternatives to {Competitor}"** → Markdown + Google Doc handoff (see
  the competitive agent's deliver step).
- **Existing post update** → Google Doc with a changes list and the updated
  article body, gated on a human review step. WordPress PATCH happens only
  on explicit ask, and only via [`../wordpress/SKILL.md`](../wordpress/SKILL.md).
- **Source video → article** → Polished, style-checked Markdown draft from
  the video-article pipeline; promote to WordPress via the same
  Doc → WordPress route.
- **Aparna Dhinakaran X post → blog** → WordPress draft built from one or
  more Aparna X posts, via the dedicated agent.

## Inputs

Ask the user (or infer) before running:

1. **Source type** — see routing table below.
2. **Source reference** — `arize.com` URL or slug, Google Doc URL,
   glossary topic, buyer's-guide topic, competitor name (for
   "Alternatives to ..."), source video URL or local file, or X post URL(s).
3. **Optional**: category/tag override for blog posts, glossary settings
   overrides, target audience tweaks, or a "preserve `tmp/`" flag for
   batch reruns of the longform agents.

## Multi-step composition

Common composed flows:

1. **Refresh review → update**: `refresh-and-decay` produces a ranked URL
   list → `update-agent` per URL → optional WordPress PATCH on explicit ask
   via the `wordpress` skill.
2. **Buyer's guide / competitive → blog draft**: run the agent end-to-end
   (Doc handoff), then route the approved Doc through the `wordpress` skill
   to land a `status=draft` post.
3. **Video → blog draft**: `video-article-pipeline` end-to-end (polished
   Markdown + style-guide pass), then `wordpress` to stage as a draft.
4. **Glossary**: `glossary-term` per topic → `wordpress/glossary/glossary-builder`
   to stage the CPT draft → `wordpress/glossary/index-page-builder` once
   per batch to refresh the alphabetized index page.

Run each sub-agent end-to-end before composing; do not interleave drafting
and CMS writes inside a single sub-agent invocation. For agents that
declare a restart-on-touch rule (e.g. the buyer's-guide and competitive
pipelines), any touch to their inputs restarts the full pipeline.

## Default = drafts, not live

- All WordPress writes use `status=draft` (or `status=publish` only on
  explicit user instruction).
- `update-agent` does not PATCH WordPress; its end state is the Doc handoff,
  and any CMS write is a separate, human-gated `wordpress` invocation.
- `aparna-x-to-wordpress` and `wordpress/glossary/glossary-builder` always
  set `status=draft` on creates.
- Longform agents (buyer's-guide, competitive, video-article-pipeline) stop
  at their deliver step on a failed eval / scorecard — no Doc handoff in
  that case; restart from step 01.

## House style (shared)

Apply on every WordPress-bound run:

- Sentence-case headings consistent with [`references/content/formatting.md`](../../../../references/content/formatting.md).
- On-brand voice per [`references/content/voice-and-tone.md`](../../../../references/content/voice-and-tone.md)
  and approved language in [`references/content/brand-lexicon.md`](../../../../references/content/brand-lexicon.md).
- Pre-publish checks per [`references/content/evaluation.md`](../../../../references/content/evaluation.md).
- Internal Arize links: relative or absolute `arize.com` URLs without
  `target` / `rel`; external links: `target="_blank" rel="noopener noreferrer"`.

## Common end state

Every successful run reports:

- Sub-agent(s) / sub-skill(s) that ran.
- For blog / glossary: post title, edit URL
  (`/wp-admin/post.php?post={id}&action=edit`), slug, category, tags.
- For longform: Markdown path under the agent's `tmp/`, Doc URL.
- For `update-agent`: source URL, Doc URL, and a short Changes note.

## Safety

- Default = `status=draft`. Never publish to `arize.com` live without an
  explicit ask.
- Don't introduce claims that aren't sourced or pre-approved.
- Don't log WordPress application passwords, OAuth tokens, or model API
  keys.
- For the glossary route, never delete prior entries; the builder upserts
  by slug.

## End of run

Per [`../../../../references/agent-runtime.md`](../../../../references/agent-runtime.md):

1. Update `last run` in this `SKILL.md` and in the sub-agent / sub-skill(s)
   that ran (today's ISO date).
2. If a WordPress write happened in a follow-up `wordpress` run, confirm
   the post status, category, tags, and slug match the source Doc.
3. Flag any new content type that should get its own sub-agent or sub-skill
   so it can be added to the routing table here.
